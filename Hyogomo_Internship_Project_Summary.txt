1. PROJECT OVERVIEW:
--------------------
During my summer internship at Hyogomo, I developed a full-stack, AI-driven Fleet Management Dashboard. The system is designed to streamline logistics operations by managing vehicles, drivers, and trips, while actively predicting maintenance needs using Machine Learning to prevent vehicle breakdowns and reduce operational costs.

2. TECHNOLOGY STACK:
--------------------
- Frontend: React.js (Vite), Tailwind CSS (for modern UI/glassmorphism), Recharts (data visualization), React-Leaflet (maps).
- Backend: Python, Django, Django REST Framework (DRF).
- Machine Learning: Scikit-Learn (Random Forest Classifier), Pandas, NumPy.
- Map & Routing: OpenStreetMap (Nominatim API for geocoding) and OSRM (Open Source Routing Machine for distance/routing).
- Reports: ReportLab (PDF generation), OpenPyXL (Excel generation).

3. KEY FEATURES DEVELOPED:
--------------------------
* AI Predictive Maintenance: Built a Scikit-Learn Random Forest pipeline that analyzes vehicle telemetry (fuel efficiency, age, service count, total trip distance, days since last service) to output a Failure Risk Probability (%).
* Smart Trip Scheduling: Integrated an interactive map using Leaflet. Users can input origin and destination; the system automatically geocodes the locations, plots the optimal driving route, and extracts the exact road distance in kilometers using the OSRM API.
* Fleet & Driver Management: Full CRUD functionality to track vehicle status, driver availability, and assignment history.
* Automated Reporting: Developed backend endpoints to generate downloadable PDF and Excel audit sheets for both general fleet manifests and AI health diagnostics.
* Real-Time Analytics Dashboard: Visualized key fleet metrics (active trips, maintenance alerts, vehicle health) using Recharts.

EXPECTED VIVA / INTERVIEW QUESTIONS & ANSWERS
================================================================================

Q1: What problem does your project solve for logistics companies?
A: It digitizes paper-based fleet tracking and, more importantly, shifts maintenance from "reactive" (fixing after a breakdown) to "predictive" (fixing before it breaks). This reduces vehicle downtime, saves money on major repairs, and ensures drivers aren't stranded during trips.

Q2: Why did you choose Random Forest for the predictive maintenance model?
A: Random Forest handles non-linear relationships well and is robust against overfitting due to its ensemble nature (it builds multiple decision trees and averages them). It also provides "Feature Importance," which allows the dashboard to explain exactly WHY a vehicle needs maintenance (e.g., showing that "vehicle age" or "poor fuel efficiency" is the primary risk factor).

Q3: How does the map and routing system work without paid APIs like Google Maps?
A: I implemented a completely open-source mapping stack. I used React-Leaflet to render the map interface. For converting city names to coordinates (Geocoding), I integrated the Nominatim API (from OpenStreetMap). For calculating the actual driving route and road distance between those coordinates, I integrated the OSRM (Open Source Routing Machine) API. 

Q4: How did you handle data imbalance in your Machine Learning model?
A: In the real world, vehicle failures are much rarer than healthy vehicles. During the Random Forest model training pipeline, I used the `class_weight="balanced"` parameter to ensure the model penalizes misclassifying a failing vehicle more heavily, ensuring it doesn't just guess "healthy" every time.

Q5: Can you explain the flow of data when a user schedules a trip?
A: 
1. The user inputs the source and destination strings in the React frontend.
2. The frontend fetches coordinates from the Nominatim API.
3. Those coordinates are sent to the OSRM API to fetch the route geometry and distance.
4. The map updates with a polyline, and the distance field auto-fills.
5. On submit, the data is sent via an Axios POST request to the Django REST Framework backend.
6. Django saves the trip to the database and automatically updates the assigned driver's status to "ON_TRIP".

Q6: How did you structure your Django backend?
A: I used an app-based modular architecture. The project is divided into specific apps like `vehicles`, `drivers`, `trips`, `maintenance`, `reports`, and `ml`. This keeps the business logic separated, making the code highly maintainable and scalable.
